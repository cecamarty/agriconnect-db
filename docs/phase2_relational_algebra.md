# AgriConnect: Farm-to-Market Platform with Mobile Money Wallet
## Phase 2: Relational Mapping Rules & Formal Relational Algebra

---

### 1. Conceptual-to-Relational Mapping Transformation

| ER Construct | Relational Implementation Rule | AgriConnect Mapping |
| :--- | :--- | :--- |
| **Strong Entity** | Direct Table Creation with Primary Key | `towns (town_id PK)`, `users (user_id PK)`, `products (product_id PK)` |
| **1:1 Relationship** | Foreign Key with `UNIQUE` Constraint | `wallets (user_id FK, UNIQUE)` references `users(user_id)` |
| **1:M Relationship** | Foreign Key in child table referencing parent PK | `users(town_id)` references `towns(town_id)` |
| **M:N Relationship** | Dedicated Junction Table with foreign keys to both parents | `order_items` references `orders` and `products` |
| **Weak Entity** | Table with Foreign Key inheriting parent PK, cascades | `wallet_txns` references `wallets`; `order_items` references `orders` |
| **Associative Entity** | Junction Table with surrogate PK and composite Unique constraint | `reviews (review_id PK, UNIQUE(buyer_id, product_id))` |

### 2. The 5 Formal Relational Algebra Expressions & SQL Verifications

#### **Query 1: Fruit Products Catalog**
- **Business Requirement:** Retrieve the names of all products categorized as 'FRUIT'.
- **Relational Algebra:**
  $$\pi_{product\_name} \left( \sigma_{category = 'FRUIT'} (Products) \right)$$
- **Relational Operators:**
  - Selection ($\sigma$): Filters tuples where $category = 'FRUIT'$.
  - Projection ($\pi$): Restricts the resulting relation to the attribute $product\_name$.
- **Verified SQL Implementation:**
```sql
SELECT product_name 
FROM products 
WHERE category = 'FRUIT';
```

---

#### **Query 2: High-Balance Wallet Holders**
- **Business Requirement:** Retrieve the full names of all users possessing a wallet balance greater than 500,000 UGX.
- **Relational Algebra:**
  $$\pi_{full\_name} \left( Users \bowtie_{Users.user\_id = Wallets.user\_id} \left( \sigma_{balance > 500000} (Wallets) \right) \right)$$
- **Relational Operators:**
  - Selection ($\sigma$): Selects wallets with $balance > 500000$.
  - Theta/Natural Join ($\bowtie$): Equi-joins filtered wallets with users on $user\_id$.
  - Projection ($\pi$): Retains attribute $full\_name$.
- **Verified SQL Implementation:**
```sql
SELECT u.full_name 
FROM users u 
JOIN wallets w ON u.user_id = w.user_id 
WHERE w.balance > 500000.00;
```

---

#### **Query 3: Order Demand Aggregated by Town**
- **Business Requirement:** Compute the total count of orders placed from each town.
- **Relational Algebra:**
  $$\pi_{town\_name, order\_count} \left( _{town\_name} \mathcal{G}_{COUNT(order\_id) \rightarrow order\_count} \left( Towns \bowtie Users \bowtie_{users.user\_id = orders.buyer\_id} Orders \right) \right)$$
- **Relational Operators:**
  - Natural Join ($\bowtie$): Combines towns with users and orders.
  - Aggregate Grouping ($\mathcal{G}$ or $\gamma$): Groups tuples by $town\_name$ and calculates $COUNT(order\_id)$.
  - Projection ($\pi$): Selects $town\_name$ and the computed count.
- **Verified SQL Implementation:**
```sql
SELECT t.town_name, COUNT(o.order_id) AS total_orders 
FROM towns t 
JOIN users u ON t.town_id = u.town_id 
JOIN orders o ON u.user_id = o.buyer_id 
GROUP BY t.town_name;
```

#### **Query 4: Top-Rated 5-Star Products**
- **Business Requirement:** List the names of all products that have received a perfect 5-star customer review.
- **Relational Algebra:**
  $$\pi_{product\_name} \left( \sigma_{rating = 5} (Reviews) \bowtie_{Reviews.product\_id = Products.product\_id} Products \right)$$
- **Relational Operators:**
  - Selection ($\sigma$): Restricts reviews to tuples where $rating = 5$.
  - Join ($\bowtie$): Joins with $Products$ on matching $product\_id$.
  - Projection ($\pi$): Displays unique $product\_name$.
- **Verified SQL Implementation:**
```sql
SELECT DISTINCT p.product_name 
FROM products p 
JOIN reviews r ON p.product_id = r.product_id 
WHERE r.rating = 5;
```

---

#### **Query 5: Cumulative Sales Revenue by Product**
- **Business Requirement:** Compute the total sales revenue (sum of line totals) generated by each product.
- **Relational Algebra:**
  $$\pi_{product\_name, total\_sales} \left( _{product\_name} \mathcal{G}_{SUM(line\_total) \rightarrow total\_sales} \left( Products \bowtie_{Products.product\_id = Order\_Items.product\_id} Order\_Items \right) \right)$$
- **Relational Operators:**
  - Equi-Join ($\bowtie$): Combines catalog products with their fulfilled order items.
  - Aggregate Grouping ($\mathcal{G}$): Groups by $product\_name$ and computes $SUM(line\_total)$.
  - Projection ($\pi$): Projects $product\_name$ and aggregate sum.
- **Verified SQL Implementation:**
```sql
SELECT p.product_name, SUM(oi.line_total) AS total_sales_ugx 
FROM products p 
JOIN order_items oi ON p.product_id = oi.product_id 
GROUP BY p.product_id, p.product_name;
```
